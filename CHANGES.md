## Correction: impersonation is not detectable by TLS fingerprint
- Retracted an earlier result claiming curl-impersonate profiles were flagged. Real Chromium builds (107 to 143, `dataset/lab/fetch_chromium.sh`, dataset v0.4) have the identical JA4 to the same-era profiles (`eval/fidelity.py`), so those feed entries were real Chrome's fingerprint.
- `make_intel_feed.py` no longer lists impersonation profiles; it lists real Chromium builds and libraries as benign (34 rows). Total bundled fingerprints: 305.
- `--shared-network <CIDR>` (and `TLSFP_SHARED_NETWORKS`) for `pcap`, `live` and `serve`; rotation and monoculture skip those addresses. A fingerprint with an exact benign match is never a monoculture.
- Recognises Node.js, Ruby, PHP, OpenSSL and Go labels as non-browser families.
- New scenario lab (`dataset/lab/run_scenarios.py`, dataset v0.5) and evaluators (`eval/scenarios.py`, `eval/crosslayer.py`) for the cleartext-HTTP rules.
- New rule `header_anomaly`: a browser User-Agent on a cleartext request to a non-loopback origin that carries `Sec-Fetch-*`, `Sec-CH-*` or an h2c upgrade. Registered in the dashboard.
- Detection evaluation now also reports the NAT scenario with the address declared shared (30 `fp_rotation` alerts to 0).

## Real full Chrome and a second correction
- Found that real full Chrome builds are downloadable from Chrome for Testing (`dataset/lab/fetch_chrome.sh`); an earlier statement that real desktop Chrome was out of reach was my error. Dataset v0.6: 31 builds (113 to 143), 25 of which produced traffic, beside 20 impersonation profiles.
- The fidelity result is configuration-dependent, which qualifies the v0.4 conclusion: profiles equal Chromium headless shells (8 of 9) but differ from the lab's full Chrome (0 of 25) in ECH, the ALPS codepoint (127 to 131) and trust anchors (141+). The lab could not make Chrome send ECH, so the question of typical desktop users stays open. Docs and feed policy wording corrected; profiles are still never listed.
- `eval/fidelity.py` reports the extensions that differ per build and excludes builds that produced no traffic.

## Field observations on desktop browsers
- `scripts/capture-browser.ps1` and `docs/BROWSER_CAPTURE.md` record a real Windows browser with pktmon. The decoder now reads the raw 802.11 frames pktmon writes for Wi-Fi under an Ethernet label, and the capture summary reports skipped-frame counters with a warning when a capture decodes to nothing.
- First results (`docs/FIELD_OBSERVATIONS.md`): Brave 1.98.60 and Edge 155.0.4283.62 send the same JA4, with ECH and the new ALPS codepoint, and it equals the curl-impersonate `chrome150` profile's. This answers the open question above for one desktop machine: ECH did not separate real Chromium from the profile. The lab's missing ECH was a lab limit. The hash stays out of the feed.

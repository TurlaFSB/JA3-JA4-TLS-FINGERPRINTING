## Capture library and a quieter dashboard
- `tlsfp serve --library DIR` (env `TLSFP_LIBRARY`, repeatable) finds `.pcap` and `.pcapng` files in a folder, reads each once, and names the client in it: from an exact intelligence match when there is one, otherwise from the shape of the ClientHello (ALPS means Chromium; `record_size_limit` with `delegated_credentials` means Firefox; `encrypt_then_mac` means OpenSSL). New and changed files are picked up every 20 seconds. Analysis only: nothing is alerted or written to the database; symbolic links are not followed; only relative names are shown. `tlsfp identify FILE|DIR...` does the same from a terminal.
- `eval/identify.py` checks the family rules against the labelled lab captures with an empty database: 74 of 74 browsers and profiles named with the right family, 0 of 21 libraries called a browser. The rules were written after reading those captures, so this is a regression check, not an out-of-sample accuracy.
- Library page in the menu (Scope, Alerts, Library, Intel). The Docker stack mounts `tlsfp-captures` in the user's home folder read-only at `/captures`, where the Windows capture script saves, so captures appear without configuration.

## Live capture under load
- Fixed a missed-handshake bug found by a load test: a client that reused its source port while the old flow was still tracked was never fingerprinted again. A SYN with a new initial sequence number now starts a new flow (`flows_restarted`). The kernel capture buffer is 32 MiB (was 4), the frame channel 4,096 (was 512), `TLSFP_CAPTURE_BUFFER_MIB` overrides it. Results and a multi-process scaling table are in `docs/PERFORMANCE.md`; AUDIT.md F18 and F19.

## Your own detection rules
- `--rules FILE` (or `TLSFP_RULES`) loads detection rules from a TOML file: conditions on the event type, server name globs, fingerprints, client family, intelligence verdict, ALPN, transport, TLS version, extensions, source and destination networks and ports, with `unless` vetoes and a `once_per` limit so a beacon raises one alert. A file with an unknown key or value, a duplicate name or a rule with no condition is refused with the rule named; `tlsfp rules check FILE` validates it. Alerts carry the rule `custom`, the rule name as the title and what matched in the detail. `docs/RULES.md`, `examples/rules.example.toml`, tests through the real binary.
- `tlsfp ... | head` no longer prints a panic backtrace when the reader of the pipe leaves.

## Per-host history
- `/api/hosts` and `/api/hosts/{ip}` build a profile per address from the stored observations: first and last seen, every client fingerprint with when it appeared and disappeared, servers contacted, User-Agent and OS claims, and alerts raised. A Hosts page in the dashboard shows a timeline per host; a client that appears later is the sign that something on the host changed. Profiles exist only while detection runs, because they are built from the observation table.

## Alert delivery
- `--alert-file`, `--alert-syslog` (RFC 5424 over UDP or TCP) and `--alert-webhook` (http or https; generic, Slack or Discord body) forward each stored alert, with `--alert-min-severity` as a floor. A bounded queue and one worker thread keep a slow destination from stalling capture; drops and failures are counted on `/metrics`. One-shot commands wait for the queue at exit. Adds the `ureq` HTTP client with rustls (`ring`); `cargo deny check licenses` passes. `docs/ALERTS.md`, tests through the real binary.

## One-click report
- `tlsfp html FILE... -o report.html` writes a single self-contained page per run: file name, SHA-256, size, first and last packet time, handshake counts, the most likely client and its confidence, every client with its servers, the detection rules that fired with a plain-language reason, and the limits of those claims. No script and no network request; every value from a capture is HTML-escaped (tested with a hostile server name). Detection runs on a private copy of the intelligence database, so your own is untouched. The Library page has a "Download report" link per capture (`/api/library/{id}/report`; an id not in the listing is a 404, so a request cannot name a path).
